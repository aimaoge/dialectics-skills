# 复盘引导（定时任务触发时使用）

> 复盘定时任务触发时，先读取本文件，再按以下引导回访用户。
> 目标：把"一次性对话"变成"持续跟进"——检验处方是否落地、是否要调整。
> 前置：先找到并读取上次的 `问题诊断-行动处方.md` 和 `2周行动日历.md`（如果生成了），不要凭记忆。

## 一、回访开场
- 先问候，说明这是上次分析的定期复盘。
- 简短重述上次处方要点（主要矛盾 + 推荐方案 + 最小动作），让用户立刻想起上下文。

## 二、四个复盘问题（逐个温和地问，不审问）
1. 上次定的"今天就能做的第 1 件事"，做了吗？结果怎样？
2. 处方里的观察指标，有没有出现变化？（例如：面试邀约数、完成天数、存款变化）
3. 卡在哪里？是没动力、方法不对、还是目标本身要调整？
4. 方向还对吗？要调整处方吗？

## 三、按反馈分路处理
| 用户反馈 | 处理 |
|---|---|
| 有进展、方向对 | 肯定，再定一轮新的"最小动作"，继续推进 |
| 卡住、没动力 | 回到六步法定位卡点（是任务太大/完美主义/缺约束？），重新给最小动作 |
| 方向不对、要换 | 重跑"找准主要矛盾"，重新定方案 |
| 不需要了/问题解决 | 尊重并结束，按 doubao-cron-scheduler 删除该定时任务 |

## 四、复盘后必做
1. **更新处方文件**：保留原记录，追加一行"复盘状态"，把新结论写进去，重新交付。
2. 如果继续跟进，更新复盘定时任务的到期时间（按 doubao-cron-scheduler 规范）。
3. 向用户说明：处方已更新、下一步是什么、什么时候再看一次。

## 注意事项
- 复盘的目的是**支持而不是监督**，语气保持"我陪你推进"，不要变成"考核你完成没有"。
- 用户没动力时，先问卡点（任务太大/完美主义/缺约束），再给新的最小动作，语气保持支持。
