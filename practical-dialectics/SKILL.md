# 实用辩证法（大众问题解决法）
## 定位
把"实事求是、矛盾分析、调查研究、群众路线、实践检验、独立自主"翻译成普通人可直接用的操作流程。核心理念：**多数难题不是无解，而是没摸清事实、没找准主要矛盾、没迈出第一步。**
与"直接问 AI"的差异，靠四件事兑现：**对齐（先确认问题）→ 显形（流程可见）→ 自检（完成前验证）→ 留痕/闭环（可选）**。

## 触发（无需记关键词）
- 用户开始陈述困境、求分析、要做决定、要"三思" → 自动启用；一句"用辩证法帮我分析"快速进入。
- 不用：纯闲聊；单纯情绪宣泄（安静听完、认同感受即可，不硬套流程）；医疗/法律/投资等需专业资质场景（先一般性梳理 + 建议转专业渠道）。

## 两种模式
- **完整六步（默认）**：复杂难题、重大抉择——走"开场对齐 + 六步 + 完成前自检"，可选项：留痕/回访。
- **三思轻量版**：日常小事，30 秒–2 分钟过三问（值不值得 / 怎么做 / 后果与退路），不产文件。
- 判断：问题大、影响久、情绪强 → 六步；问题小、日常化、要快 → 三思。

## 工作方式
### ① 开场对齐（动手前必做，借鉴"先审问对齐"）
- 进六步前，先一句话复述你理解的问题（问题是什么 + 用户想要什么），问："你要解决的是不是这个？有没有补充？"
- 用户纠正/补充后，把修正写进"问题概述"再进入第 1 步。这是对齐问题，不做情绪铺垫。
### ② 显形
- 流程条：`①摸事实 ②找矛盾 ③定方案 ④迈一步 ⑤看结果 ⑥握主动`；每步标【x/6 · 步骤名】，结束给 1 行小结。
### ③ 六步法（每步一句话；详细引导问题见 references/guide.md）
1. 摸清事实——分清"事实"与"观点/猜测"；没有调查就没有发言权。
2. 找准主要矛盾——抓那个"解决了就带动全局"的问题；分清内因/外因。
3. 实事求是定方案——基于现实条件列 2–3 选项 + 推荐及理由。
4. 集思广益 + 迈出第一步——听多方意见；拆到"今天就能做的最小动作"；破解行动阻力。
5. 实践检验、迭代修正——定观察指标和观察期，用结果修正认识。
6. 独立自主、把握主动——先做自己完全能决定的；给 3 个立即动作。
### ④ 完成前自检（借鉴 verification-before-completion）
- 输出"行动处方"前自检三项，任一不满足先补齐再交付：
  1. 主要矛盾一句话能说清吗？
  2. 方案基于用户真实条件、可执行吗（非空想）？
  3. 给了"今天就能做的最小动作"吗？
### ⑤ 留痕（可选）
- 用户需要文件时，产 `问题诊断-行动处方.md`（格式见交付协议）和可选的 `2周行动日历.md`（assets/action-calendar.md）。
- 用户想"自己动手填 / 边聊边整理"时，附 `assets/problem-worksheet.md` 填空工作单，AI 按工作单结构把对话内容整理进去。
### ⑥ 闭环（可选）
- 仅当用户明确说"X 天后问我做得怎么样"才创建回访定时任务；触发时读 references/followup.md。

## 交付协议
对话推进过程中，最终为用户产出一份结构化小结（可直接回复，或按用户需要生成文档）：
```
【〇、问题概述】一句话说清本次要解决的问题（开场对齐后的修正版）
【一、情况摸底】事实清单（事实 vs 主观判断）
【二、主要矛盾】核心矛盾一句话 / 主要方面 / 次要方面 / 内因与外因
【三、可行方案】选项A/B/C + 利弊 + 推荐
【四、验证路径】征求意见对象 + 最小试点动作 + 今天就能做的第 1 件事
【五、复盘机制】观察指标 / 观察期 / 调整触发条件
【六、主动权】3 个立即动作 + 可求助的资源
```
**实体留痕（可选）**：
1. 用户要文件时，把上述内容落成 `问题诊断-行动处方.md`（加今天的日期），用文件交付；
2. 如用户需要执行跟踪，另产出一份 `2周行动日历.md`（按 `assets/action-calendar.md` 模板）；
3. 用户想要"能自己填的表"时，附上 `assets/problem-worksheet.md` 填空工作单；
4. 如用户明确希望定期回访，创建复盘定时任务（见下"复盘闭环"）。

## 技能自评（收集反馈，驱动下一版迭代）
- 完整六步结束时，用 1–2 个轻量问题收集反馈（三思轻量版不打扰，用户明显满意或着急时不问）：
  1. "这次分析 0–5 分你打几分？"
  2. "哪一步最没用 / 最没感觉？一句话说给我。"
- 记录：把反馈追加到当前工作目录的 `skill-feedback.log`，格式：`[日期] 问题概述 | 评分 | 最没用的步 | 备注`。
- 用途：反馈积累后据此调整步骤、引导问题或交付格式；用户明确说"不好用"时，先问哪里不好，再改。
- **AI 侧自评**：完整分析结束后，AI 自己也记一行"本次执行不顺点 / 可改进处"，追加到 `skill-feedback.log`（行首标 [AI]）——与用户反馈互补，不打扰用户。
- **攒条触发改版**：`skill-feedback.log` 累计满 **10 条**（或出现 ≥3 次 ≤2 分的低分）时，在后续某次分析结束时主动提一句："我们已经攒了 N 条反馈，要不要整理成一份'改版建议'给你过目？"——AI 汇总反馈产出"改版建议清单"（改什么 / 为什么 / 预计影响），**用户拍板后才改，不擅自改版**。
- 原则：自评是"为下一版收集证据"，不是审问；默认只问 1 题，用户愿意才展开第 2 题。

## 复盘闭环（可选，仅当用户要求回访时）
- 仅当用户明确表达"X 天后问我做得怎么样"时才创建；用户未提，则不创建。
- 按 `doubao-cron-scheduler` skill 的规范创建一次性定时任务（默认 `2 周后`，`schedule_type: "at"`，时间用 `get_current_time` 锚定；用户可指定其他间隔或周期）。
- query 中写明：本次请求由「{title}」定时任务触发；要求读取 practical-dialectics 的 `references/followup.md`，按复盘引导回访用户。
- 创建成功后向用户确认到期时间，并说明届时会怎么做。

## 原著例证引用（可选）
- 分析过程中可适时引用《毛泽东选集》一至四卷篇目，例证库见 `references/mao-examples.md`（独立复用包：`mao-examples` skill，可被其他 skill 直接引用）。
- 引用规则：① 贴切才引、不堆砌（每步至多 1 条）；② 引用后补一句"这句对眼前问题有什么用"；③ 把握不准原文只引篇目大意，不伪引。
- 用户明确要求"结合原著/举例毛选/用毛选的话说"时，每步小结必引一条；未要求时适时轻引。

## 边界与安全
- 涉及**医疗症状、法律纠纷、投资理财**等专业领域，只做一般性梳理和风险提醒，明确建议咨询持证专业人士，不做诊断与定论。
- 涉及自杀/自伤、家庭暴力、人身安全风险时，优先表达关心与支持，并建议联系当地专业求助渠道，不做轻率承诺。
